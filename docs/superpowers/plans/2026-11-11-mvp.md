# Merchant Portal MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed, demo-ready merchant portal (Phase 0) showing the insights, operations and assistant layers working end-to-end on synthetic NETS-style data.

**Architecture:** A Next.js 15 App Router app on Vercel talks to a hosted Supabase Postgres. Pages are server components that read through `lib/` service functions using the logged-in user's session, so Row Level Security isolates merchants. Heavy aggregation runs in SQL functions. Business logic (metrics, headline text, reconciliation, nudges) is pure TypeScript and unit-tested. The copilot is a streaming route handler that calls Claude with a fixed set of read-only tools, each of which calls the same `lib/` service functions.

**Tech Stack:** Next.js 15, TypeScript, Tailwind CSS, shadcn/ui, Recharts, TanStack Table, Supabase (`@supabase/ssr`, `@supabase/supabase-js`), `@anthropic-ai/sdk`, Zod, ExcelJS, `@react-pdf/renderer`, Vitest, Playwright.

**Spec:** `docs/01-project-plan.md` (Phase 0 table), `docs/02-technical-design.md`, `CLAUDE.md` (Design section = chosen A+B hybrid).

## Global Constraints

- Money is stored as **integer cents** (`bigint`) and displayed as `$1,234.56` (SGD, `en-SG`).
- Timestamps are `timestamptz`. All day/hour bucketing is done in **`Asia/Singapore`**.
- Channels enum, exactly: `nets_qr`, `nets_click`, `enets`, `card`, `sgqr`. Display labels: `NETS QR`, `NETS Click`, `eNETS (online)`, `Cards`, `SGQR`.
- Every merchant-owned table has `merchant_id` plus an RLS policy using `is_merchant_member(merchant_id)`. The service-role key is used only in `scripts/`, never in `app/`.
- The AI never writes SQL. It may only call the tools in Task 12, which are read-only.
- Model `claude-opus-5-5`, with server-side refusal fallback (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`).
- UI follows the CLAUDE.md "Design" section: navy sidebar `#0E1726`, accent `#1F4FD1`, ground `#F6F5F1`, Inter, white 20px-radius cards, touch targets ≥ 44px, plain-English labels with the technical term underneath.
- Copy is plain English: no jargon without a plain-language label beside it.
- Must work at 375px width with no horizontal page scroll.
- Synthetic data only. No real PII.

## Review Focus

1. **A merchant with no data for the selected period** (new merchant, future date range). Expect "No sales yet for this period" empty states, never `NaN`, `$NaN` or `Infinity%`. The test lives in Task 6 (`comparePeriods` with a zero previous period, `buildHeadline` with zero sales).
2. **Cross-merchant access via URL or the assistant** (e.g. `/transactions/<other merchant's id>`, or "show me Tan & Sons' sales"). Expect "not found" or a refusal. Tests: RLS check in Task 2; assistant tool test in Task 12.
3. **Week and month boundaries in Singapore time.** A 23:30 SGT payment counts on that SGT day, not the UTC day. Test in Task 2 (`get_daily_sales` buckets by SGT) and Task 6.
4. **Rounding in fees/recon.** Sums of cents must match exactly, with a 1-cent tolerance only where the spec says (`> 1` cent difference = mismatch). Test in Task 11.
5. **The assistant asked for something it has no tool for** (e.g. "change my bank account"). Expect it to say it can't do that here and point to the right page, never inventing a number. Test in Task 12 (system prompt eval case).
