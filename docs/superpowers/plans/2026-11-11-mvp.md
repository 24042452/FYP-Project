# Merchant Portal MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed, demo-ready merchant portal (Phase 0) showing the insights, operations and assistant layers working end-to-end on synthetic NETS-style data.

**Architecture:** A Next.js 15 App Router app on Vercel (React front end, Node.js back end) talks to a **MySQL 8** database through `mysql2/promise`. Pages are server components that read through `lib/data/` functions. Each function takes the logged-in merchant's id (from the server session, never from the request) and filters every query by `merchant_id`; this replaces database row-level security. Aggregation is plain SQL in `lib/data/`. Business logic (metrics, headline text, reconciliation, nudges) is plain JavaScript and unit-tested. The copilot is a streaming route handler that calls Claude with a fixed set of read-only tools, each of which calls the same `lib/data/` functions.

**Tech Stack:** Next.js 15 in **plain JavaScript (no TypeScript)**, Tailwind CSS, shadcn/ui, Recharts, TanStack Table, **MySQL 8 + `mysql2`**, `bcryptjs` (own login + sessions), `@anthropic-ai/sdk`, Zod, ExcelJS, `@react-pdf/renderer`, Vitest, Playwright.

**Spec:** `docs/01-project-plan.md` (Phase 0 table), `docs/02-technical-design.md` (v0.2, MySQL), `docs/adr/001-mysql-database.md`, `CLAUDE.md` (Design section = Option 1 · Clean Console), mockups in `design/` (open `design/index.html`).

> **Changed 2026-11-14:** database switched from Supabase Postgres to MySQL (firm project requirement; ADR-001). Tasks 1b, 2, 4, 5, 6, 12 and 14 were updated for it.

## Global Constraints

- Money is stored as **integer cents** (`BIGINT`) and displayed as `$1,234.56` (SGD, `en-SG`).
- Timestamps are `DATETIME(3)` in **UTC** (pool option `timezone: 'Z'`). All day/hour bucketing is done in **Singapore time** with `CONVERT_TZ(col, '+00:00', '+08:00')` (fixed offset; Singapore has no DST).
- Channels enum, exactly: `nets_qr`, `nets_click`, `enets`, `card`, `sgqr`. Display labels: `NETS QR`, `NETS Click`, `eNETS (online)`, `Cards`, `SGQR`.
- **Merchant isolation (no RLS in MySQL):** SQL lives only in `lib/data/`. Every exported data function takes `merchantId` as its first argument and every query on merchant-owned tables has `WHERE merchant_id = ?`. Pages, routes and assistant tools get `merchantId` only from `getCurrentMerchant()` (server session), never from URL params, request bodies or the model. Every data function gets a cross-merchant case in `tests/integration/isolation.test.js`.
- **Prepared statements only** (`pool.execute(sql, params)` with `?` placeholders). Never concatenate user input into SQL.
- The `mysql2` pool sets `decimalNumbers: true`, `supportBigNumbers: true`, `timezone: 'Z'`, `dateStrings: ['DATE']` so `SUM()` results are numbers and DATE columns come back as `'YYYY-MM-DD'` strings. The admin DB user (migrations, seeding) is used only in `scripts/`; the app uses a user with `SELECT, INSERT, UPDATE, DELETE` only.
- The AI never writes SQL. It may only call the tools in Task 12, which are read-only.
- Model `claude-opus-5-5`, with server-side refusal fallback (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`).
- **Plain JavaScript only (decided 2026-11-12; the team has not learned TypeScript).** Files are `.js` / `.jsx` (`.mjs` for Node scripts and configs). No `tsconfig.json`, no type annotations, no `@types/*` packages. Function signatures and data shapes in this plan are written TypeScript-style **for documentation only**: write them in code as JSDoc comments (`/** @param {number} cents @returns {string} */`, `/** @typedef {...} DailySalesRow */`). Runtime checks use Zod (assistant tool inputs, form inputs). The `@/*` import alias is set in `jsconfig.json`.
- UI follows the CLAUDE.md "Design" section and the `design/` mockups (Option 1 · Clean Console): light sidebar, page `#F5F7FA`, white panels with 1px `#E2E7EE` borders and 8–12px radius, blue `#0B4DB8` for data and navigation, red `#D3162B` for the brand mark, main action button and problems, Inter, status pills always word + colour, touch targets ≥ 44px, plain-English labels with the technical term underneath. On phones: menu button + bottom tab bar (Home, Payments, Check-up, Ask, More). Copy the CSS tokens from `design/assets/portal.css` into Tailwind theme variables.
- Copy is plain English: no jargon without a plain-language label beside it.
- Must work at 375px width with no horizontal page scroll.
- Synthetic data only. No real PII.

**Cut order if behind schedule** (agreed 2026-11-11): Task 13 (notifications) → the PDF export in Task 11 → the Coming Soon pages in Task 5 (greyed-out "Soon" nav items instead) → AI mode in Task 12.

## Review Focus

1. **A merchant with no data for the selected period** (new merchant, future date range). Expect "No sales yet for this period" empty states, never `NaN`, `$NaN` or `Infinity%`. The test lives in Task 6 (`comparePeriods` with a zero previous period, `buildHeadline` with zero sales).
2. **Cross-merchant access via URL or the assistant** (e.g. `/transactions/<other merchant's id>`, or "show me Tan & Sons' sales"). Expect "not found" or a refusal. Tests: isolation integration test in Task 2 (extended by each later data task); assistant tool test in Task 12.
3. **Week and month boundaries in Singapore time.** A 23:30 SGT payment counts on that SGT day, not the UTC day. Test in Task 2 (`getDailySales` buckets by SGT) and Task 6.
4. **Rounding in fees/recon.** Sums of cents must match exactly, with a 1-cent tolerance only where the spec says (`> 1` cent difference = mismatch). Test in Task 11.
5. **The assistant asked for something it has no tool for** (e.g. "change my bank account"). Expect it to say it can't do that here and point to the right page, never inventing a number. Test in Task 12 (system prompt eval case).

### Task 12: NETS Assistant (copilot) v1

> **Decision (2026-11-11):** The MVP ships **no-AI mode as the default** (`ASSISTANT_MODE=rules`), so the assistant works on stage without an API key. AI mode (`ASSISTANT_MODE=ai` + `ANTHROPIC_API_KEY`) is built on the **same tools and the same `search_kb`**, and it is the true RAG version (retrieve passages, then Claude writes a cited answer). Build order: tools → KB search → rules engine → chat UI → AI mode last (it can slip to Phase 2 without hurting the demo).

**Rules-mode interfaces (added):**
- `parseTimePhrase(text:string, today:string): {from:string; to:string; label:string} | null`. Recognises `today`, `yesterday`, `this week`, `last week`, `this month`, `last month`, `past N days`, weekday names ("on Friday" = the most recent one), and `in <Month>`.
- `matchIntent(text:string): {intent:'sales_summary'|'compare'|'busiest'|'channel_mix'|'failed_payment'|'settlement_status'|'invoice'|'help'; confidence:number}` uses keyword rules (e.g. take/made/sales/revenue → sales_summary; busiest/peak/popular → busiest; fail/declined/didn't go through → failed_payment; paid out/bank/settle/when will I get → settlement_status; bill/invoice/charges → invoice; vs/compare/than last → compare). Anything under 0.5 confidence → `help`.
- `answerWithRules(text, ctx:{merchantId; today; tools}): Promise<{text:string; source?:{title:string; href:string}; suggestions:string[]}>` runs the intent's tool, then fills a template. Example templates: sales → `"{label} ({from}–{to}) you made {gross} from {n} payments."`; busiest → `"Your busiest time is {slot}. Your busiest day is {day}."`; help → the top `search_kb` answer verbatim with its source; no match → `"I can't answer that yet. Try one of these:"` plus 4 suggestions.
- Tests: `tests/unit/assistant-rules.test.js`. `parseTimePhrase('how much did I take last week', '2026-11-11')` → from `2026-11-02`, to `2026-11-08`. `matchIntent('which day is my busiest')` → `busiest`. `matchIntent('change my bank account')` → `help`, and with no KB hit the answer is the "can't answer yet" text plus a link to `/requests`. No template output contains `NaN` or `undefined` for an empty period.
- The demo script uses the suggestion chips, which are guaranteed to match an intent.
